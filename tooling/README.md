# Средства сопровождения

Java 17, единая сборка с backend через Gradle Wrapper. Команды запускаются из корня курсовой: `java -Xmx512m -jar tooling/build/libs/course-tools.jar <команда>`. Из другой директории добавляется `--root <каталог-курсовой>`. Полный список — `help`.

Модуль содержит средства запуска приложения, проверки БД и работы с Helios. Сущности, словарь данных и Mermaid-модели строятся по docs/part2/model/catalog.json; исходники диаграмм классов находятся в файлах .puml. Команда reports собирает PDF из Markdown. Архивные DOCX в сборке не используются.

| Библиотека | Применение |
| --- | --- |
| [SSHJ 0.40.0](https://github.com/hierynomus/sshj) | Проверка known_hosts, SFTP, SSH-команды и локальный туннель |
| [Apache FOP 2.11](https://xmlgraphics.apache.org/fop/2.11/embedding.html) | XSL-FO, встроенные шрифты, оглавление и PDF |
| [Apache PDFBox 3.0.8](https://pdfbox.apache.org/3.0/getting-started.html) | Проверка PDF и превью для просмотра |
| PlantUML 1.2025.10 | PNG/SVG с встроенной раскладкой Smetana |
| Jackson 2.19.2 | Чтение каталога и данных титульного листа |

Gradle объединяет ServiceLoader-регистрации зависимостей при сборке toolJar: это необходимо для обработчиков изображений FOP. Готовый JAR содержит необходимые библиотеки. Для db нужен psql, для reports — каталог шрифтов COURSE_FONTS; для SSH-команд — доступ к helios и проверенный ключ в known_hosts. Пароль можно вводить скрыто или передавать через временную COURSE_SSH_PASSWORD. Пароли не записываются в журнал, аргументы процесса или файлы проекта.

verify создаёт lf3check_* и запускает существующие тесты Java-приложения; verify-db создаёт lfcheck_* и выполняет 50 SQL-проверок, три конкурентных сценария и закрытие аукциона. При занятом префиксе команды останавливаются. Имена SQL заменяются вместе с экранированными LIKE-шаблонами, чтобы seed.sql не обращался к исходным последовательностям.

deploy устанавливает backend, tooling, database, docs и файлы корня проекта в /home/studs/USER/poteryashki-course. Каждый файл проверяется по SHA-256 и заменяется атомарно. Перед записью проверяются тип файла и отсутствие символических ссылок в пути. После загрузки команда останавливает сервер курсовой, обновляет схему, выполняет launch --demo и запускает веб-сервер. Данные базы сохраняются; протокол установки находится в docs/part3/validation.
