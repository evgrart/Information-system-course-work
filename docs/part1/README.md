# Отчёт по первому этапу

Основной файл — [report.tex](report.tex): титульный лист, оформление и подключение текста. Содержание, таблицы, подписи и ссылки находятся в [content.tex](content.tex). Этот же текст используется в [общем отчёте этапов 1–2](../part1-2/report.tex). Текущие диаграммы подключаются из каталога [uml/revised](uml/revised): пять диаграмм прецедентов и общая архитектура. Готовый документ — [report.pdf](report.pdf).

Требования оформлены отдельными карточками по образцу `D:\ITMO\ITMOlabs\opi\lab1\report.pdf`: 10 функциональных и 6 нефункциональных. Пять процессов — получение доступа, публикация находки, возврат владельцу, рассмотрение спора и аукцион. Каждый содержит сюжет, участников, предусловия, основной и альтернативные потоки и отдельную диаграмму. Sequence-диаграмма в первой части не используется.

Для сборки нужен XeLaTeX (MiKTeX или TeX Live) и шрифты Times New Roman, Arial, Consolas. Пакеты перечислены в преамбуле `report.tex`.

Из корня проекта в PowerShell:

```powershell
& "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -ExecutionPolicy Bypass -File docs\part1\build.ps1
```

Скрипт выполняет три прохода для содержания, номеров страниц и ссылок. Промежуточные файлы сохраняются в `.latex-build`; PDF заменяется только после успешной сборки и проверки журнала на переполнение, пропущенные символы и неразрешённые ссылки.

Без PowerShell можно собрать документ из каталога `docs/part1`:

```sh
latexmk -xelatex -interaction=nonstopmode -halt-on-error -outdir=.latex-build report.tex
```

Результат этой команды находится в `.latex-build/report.pdf`.

ФИО авторов, группа и преподаватель указаны непосредственно в титульном листе `report.tex`; авторы PDF также задаются в `\hypersetup`. Текст первой части редактируется в `content.tex`; `report.md` содержит соответствующую текстовую версию. DOCX — архивная версия. Команда Java `reports` не заменяет PDF первой части и общего отчёта 1–2.

В схеме архитектуры различаются веб-сервер Tomcat, UML-компоненты приложения, артефакт шаблонов Thymeleaf, база данных и каталог вложений. Редактируемая компоновка находится в `uml/revised/system_architecture.layout.svg`, модель связей — в `system_architecture.puml`. Команда `diagrams` использует SVG-компоновку для получения PNG и SVG этой схемы.
