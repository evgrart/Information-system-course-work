# Повторная проверка курсовой работы

Дата: 4 октября 2026 года.

Проверены требования этапов 1–4, схема PostgreSQL, вызовы PL/pgSQL из Java, права участников, веб-формы и соответствие отчётов реализации.

| Найденная ошибка | Исправление и проверка |
| --- | --- |
| Завершённый аукцион не создавал передачу победителю | `lf_prepare_auction_handover` создаёт единственную заявку с `auction_id`, диалог и передачу. Повтор завершения сохраняет результат и подтверждения. Проверены торги без ставок и истечение подписки победителя. |
| Принятую заявку можно было отменить после первого подтверждения передачи | Запрет введён в сервисе и триггере. Передача победителю также требует рассмотрения спора модератором. |
| Автор жалобы не видел решение | В кабинете показываются только собственные жалобы и решения; уведомление сохраняется в той же транзакции. |
| Жалоба из диалога не относилась к находке | Форма передаёт идентификатор находки. Ранее созданное дело доступно участнику после окончания подписки. |
| Модератор не мог прочитать материалы спорного диалога | Добавлен доступ через открытую жалобу на находку. Закрытие дела прекращает доступ к чужому диалогу; посторонний пользователь его не получает. |
| Не было уведомлений о сообщении и окончании подписки | События доставляются через Outbox. Частный текст сообщения не копируется в уведомление. Окончание последнего периода уведомляет один раз; продление исключает ложное уведомление. |
| Каталог возвращал 24 карточки и не имел фильтра статуса | Страница ограничена 20 карточками. Фильтр публичного статуса выполняет PL/pgSQL; черновики и скрытые объявления исключены. Курсор сохраняет условия поиска. |
| Повреждённая фотография с корректной сигнатурой давала ошибку сервера | Усечённые PNG/JPEG отклоняются с HTTP 400; файл не сохраняется. |
| Проверка конкуренции зависела от порядка запуска потоков | Проверяется один успешный запрос и один предусмотренный отказ; дополнительно проверяется количество сохранённых записей. |
| Новое приложение запускалось до обновления схемы | Установка сначала останавливает свой процесс и выполняет повторяемое обновление, затем запускает Hibernate в режиме validate. |

## Результаты проверок

- 113 тестов приложения: 57 проверок хранения и бизнес-логики, 51 проверка MVC и 5 проверок файлового адаптера. Ошибок, сбоев и пропусков нет: [tests.json](tests.json), [integration.txt](integration.txt).
- 8 тестов Java-инструментов: [tooling.json](tooling.json).
- 50 условий целостности PostgreSQL, конкурентные резервы, ставки и повтор оплаты: [database-regression.txt](../../part3/validation/database-regression.txt).
- Один полный браузерный сценарий в Microsoft Edge: публикация с фотографией, модерация, заявка, диалог, два подтверждения, жалоба и решение, ставка, регистрация, подписка и каталог при ширине 390 px: [browser.txt](browser.txt), [browser.xml](browser.xml).
- После каждого интеграционного прогона временные объекты удалены. Исходные объекты и значения последовательностей сохранены: [проверка сервисов](../../part3/validation/isolation.txt), [проверка браузера](isolation.txt).

ER-модель, словарь данных и JPA-отображение заявки согласованы: 27 таблиц и 42 внешних ключа. Диаграммы классов, отчёты этапов 1–2, 1–3, 1–4 и презентация обновлены. Номера UC-03 и UC-04 в таблице интерфейса исправлены по первому этапу.

## Границы результата

Не проводились нагрузочные испытания, проверка RPO/RTO, испытания реального платёжного провайдера и SMTP. Автоматическое резервное копирование, обезличивание профиля и общий идентификатор HTTP-запроса не реализованы. Файлы хранятся в закрытом локальном каталоге; MinIO не подключён. Отдельные проверки Chrome и Firefox не выполнялись. Группа и преподаватель на титульных листах остаются незаполненными. Материалы презентации подготовлены; проведённая защита не утверждается.
